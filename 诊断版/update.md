# 更新日志

## 2.5.2

填写包名后自动显示应用名称。

- 内置 70 个常见应用的包名对照表（短视频、社交、阅读、音乐、游戏、购物、浏览器等），输入包名就能看到应用名，不用再靠包名猜。
- 列表优先显示配置文件里保存的名称，所以以前保存过的配置升级后直接带名字。
- 对照表里没有的包名：添加时会先检查设备上是否装了该应用，装了再尝试读取应用名，读不到就显示包名，不影响计时与熄屏。
- 名称只用于显示，保存时以 `# 应用名` 注释写在 `package=` 上一行，模块本身不读这一行，手改配置也不受影响。
- 本包为诊断版，同步包含以上改动。

## 2.5.1

修复 WebUI 配置保存后不生效、列表被清空的问题。

- 修正 WebUI 与 KernelSU 的 shell 接口对接方式：KernelSU 的 `ksu.exec(cmd)` 只会返回输出的**最后一行**（libsu `ShellUtils.fastCmd` 的行为），旧代码把它当成完整输出，导致多行配置读不全、列表加载后为空。
- 后果修复：在列表为空时保存会把整份配置覆盖成只有新加的那几项，现在不会再丢配置。
- 保存后会回读校验，写入或读取失败会直接在页面顶部显示真实错误（退出码 + 系统原文），不再出现「提示已保存但其实没写进去」。
- 写入增加备用通道（base64 失败时改用 `printf %b` 八进制转义），配置改用临时文件 + 原子替换，避免写一半。
- 运行状态里的日志、诊断输出现在能完整显示（此前同样只显示最后一行）。
- 诊断版同步应用以上修复。

## 2.5

首个发布版本。

- 按应用设置使用时限，范围 1–180 分钟，连续无触摸达到时限后自动熄屏。
- 内置 WebUI：添加/删除应用、调整时间、查看运行状态与日志、导入与备份配置。
- 配置热重载，保存后 10 秒内生效，无需重启设备。
- 诊断模式：自动给出「可用 / 疑似可用 / 需要自行测试」的结论。
- 测试息屏：立即执行一次完整息屏流程，用于确认按键注入是否被系统拦截。
- 本包为「诊断版」，在标准版全部功能之上，支持一键生成详细环境诊断报告。
- 更新检查走 GitHub Pages 直链，无需代理。
- 支持 arm64-v8a / armeabi-v7a / x86 / x86_64 四种架构。
